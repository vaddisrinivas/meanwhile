# Growth loops

## Primary loop

1. Install the skill.
2. The agent offers a branded, context-aware side quest.
3. The result is funny, useful, or unexpectedly specific.
4. The user screenshots the agent message or makes a share card.
5. A viewer tries the catalogue or installs the skill.

The offer itself must carry the brand: `Meanwhile | title | duration`. The website is not required in the loop.

## Repeatable content

- Weekly "best side quest an agent gave me" post.
- One short demo per task context: OAuth, Compose, release proof, browser testing, design taste.
- Community pack contributions with a strict quality bar.
- Public removal notes explaining why weak or annoying quests were cut.
- New search pages only when they answer a real waiting situation.

## Metrics worth keeping

- Skill installs or repository stars.
- Aggregate quest opens by ID if the optional Worker is deployed.
- Pack-page visits from privacy-preserving host analytics only if later justified.
- Accepted, ignored, declined, and annoyed outcomes stored by the user's own agent history.

Do not optimize completion rate. A person closing a game or ignoring a quest is not a product failure.

## Do not add yet

- Accounts or profiles.
- Streaks and daily goals.
- Sponsored or affiliate quests.
- A personalization backend.
- Notifications outside the coding agent.
- A separate Meanwhile agent.
